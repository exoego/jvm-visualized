JVM 仕様 Java SE 21 版

          
class ファイルの読み方

          

            javac が出力した Greeter.class のバイト列を、JVM 仕様の定義に沿って先頭から読みます。

            定数プールに何が入り、JVM が実行時にそれをどう解決するかを、アニメーションで示します。
          

          

            最初から読む
            JVM 仕様を開く
              
          

          

        

      


      

        

          
00題材Greeter.java

          
題材は  行の Greeter.java

          

            題材は、名前を受け取ってあいさつを返すだけの小さなクラス Greeter です。javac でコンパイルすると、
            バイトの Greeter.class ができます。このページでは、その Greeter.class を JVM 仕様のとおりに読み、JVM がそれをどう実行するかを追います。
          

        

        

      


      

        

          
01ClassFile 構造§4.1

          
ClassFile 構造体を先頭から読む

          

            Greeter.class の  バイトには、区切り文字も目次もありません。JVMS §4.1 の ClassFile
            構造体の定義どおりに先頭から順に読み、読み取った count や length の値から次の項目の長さを決めます。JVM と同じこの手順で、末尾まで読みます。
          

        

        

      


      

        

          
02定数プール§4.4 · §4.7.23

          
定数プールの中身と参照の関係

          

            バイトコードもフィールドも、クラス名やメソッド名の文字列を直接は持ちません。持っているのは定数プールのエントリ番号です。エントリどうしも番号で参照し合い、たどっていくと最後は
            Utf8 エントリの文字列に行き着きます。
          

        

        

      


      

        

          
03ソースと定数プール§3 · §4

          
ソースの各行と定数プールの対応

          

            g.greet() という 1 つの呼び出しだけで、Methodref、Class、NameAndType と 3 つの Utf8
            のエントリが要ります。javac は同じ内容のエントリを 1 つにまとめるので、2 回目の呼び出しではエントリは増えません。下線の部分を選ぶと、その行が使うエントリと、そのうち新しく作られたものを表示します。
          

        

        

      


      

        

          
04実行時の解決§2 · §5 · §6

          
実行時定数プールと記号参照の解決

          

            JVM は、定数プールにある記号参照を実際のクラスやフィールド、メソッドに結びつけます。これを解決 (resolution)
            と呼びます。解決した結果は実行時定数プールに記録され、同じエントリを使う命令は次からその結果を使います。main を 1 命令ずつ実行して、この様子を追います。
          

          

            フレームはスレッドごと、ヒープとメソッド領域はすべてのスレッドで共有します。実行時定数プールはメソッド領域の中にあります
            (§2.5)。解決をいつ行うかは実装に任されているので (§5.4)、ここでは命令が初めてエントリを使うときに解決する方式で進めます。
          

        

        

      


      

        

          
05LinkageError§5.4.3

          
実行時に参照先のメソッドがない場合

          

            class ファイルが持っているのは、呼び出し先のクラス名とメソッド名と記述子だけです。コンパイル時にあったメソッドが実行時のクラスパスにない場合でも、JVM
            はその命令を実行して解決するまで気づきません。ライブラリのバージョンが入れ替わったときに起きる LinkageError を、実際に起こして追います。
          

          

            題材は別の 3 つの class ファイルです。foo/Foo は bar/Bar の 1.0
            に対してコンパイルし、実行時には 2.0 を置いています。1.0 の buz() は、2.0 では buzz() に変わっています。
